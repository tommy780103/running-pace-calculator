# コース生成：Strava方式の調査 ＆ GraphHopper磨き込み

実施日: 2026-06-06
対象: `index.html`

## 背景
「マップが簡易的な円。理想はStravaのような指定距離でのコース自動生成」という要望を受け、(1) Stravaの仕組みと実現可能性を調査、(2) ブラウザ単体で可能な範囲で GraphHopper round_trip を磨き込んだ。

## 調査結果（要点）
- **Stravaの品質の核は「グローバルヒートマップ（実走人気度）」での重み付け**。OSM道路データ＋人気度で“よく走られる道”を優先する。これは**Stravaモバイルアプリ専用**で、**公開API（v3）では生成エンドポイントが無い**（既存ルートの読み取りのみ）。Komootも同様にヒートマップ系だが生成API非公開。
- → 「Stravaと完全に同じ品質」をAPIで再現するのは原理的に不可能（人気度データが外部提供されていない）。
- **ブラウザ単体（バックエンド無し）で到達できる現実解 = GraphHopper round_trip**。OpenRouteServiceの round_trip はブラウザCORS不可（前回実測）、OSRMは2地点のみで周回非対応。
- Strava級を目指すなら自前ホスト（Valhalla/GraphHopper＋独自重み付け）＝サーバー構成が必要。

参考: Strava Generated Routes / Strava API Docs / GraphHopper Custom Model / GraphHopper round_trip caveat / ORS round trip thread

## 実装した磨き込み（GraphHopperの範囲）
1. **大通りを避ける（custom_model）**: チェックON時、`POST /api/1/route` に `custom_model`（MOTORWAY=0, TRUNK×0.15, PRIMARY×0.3, SECONDARY×0.5 で priority 低減）を付与し、走りやすい道を優先。`localStorage`(`pace-calc:v1:avoid-main`) に保存。
   - **重要な安全設計**: `round_trip` と `custom_model` の併用はGraphHopper公式に明記が無く実機キー無しでは確証不可。そこで **POST失敗時はGETの通常round_tripへ自動フォールバック**（バッチ内で1回失敗したら以降はGET、クレジット浪費を最小化）。失敗時はステータスに「大通り回避は利用できず通常ルート」を表示。
2. **別の案を生成**ボタン: `Math.random()` で新しい seed 4つを生成して再取得（Stravaの「別候補」に相当）。起点＋キーがある時のみ有効。
3. **目標vs実測距離の表示**: 各カードに「実測 9.82 km（目標比 -0.18km）」を表示。round_trip は実距離が目標とズレやすい仕様への対策。
4. **`round_trip.points` は不採用**: 当初案だが**公式に存在しないパラメータ**だったため除外（`round_trip.distance`/`round_trip.seed` のみ使用）。

## 追加した要素
- 関数: `roadRouteLoop(lat,lng,meters,seed,key,avoidMain)`（GET/POST分岐）, `randomSeeds`, `routeAvoidMain`, `updateRegenBtn`, 定数 `AVOID_MAIN_MODEL`, `currentSeeds`。`generateCourses(seeds)` 化、`renderCourseList(list,isFallback,targetKm)` 化。
- UI: 「大通りを避ける」チェックボックス（`#route-avoid-main`）、「別の案を生成」ボタン（`#route-regen`）。
- `setRouteStatus('ok', note)` で補足メッセージ表示に対応。

## エラーと解決策（この回）
- **CORS（既出）**: ORSはブラウザ直叩き不可 → GraphHopper採用（前回対応済み）。
- **round_trip.points 誤り**: 公式に存在しないパラメータを当初検討 → 調査で確認し除外。
- **custom_model×round_trip の不確実性**: 実機キー無しで検証不能 → POST失敗時GETフォールバックで安全化。

## 【追記】GraphHopper無料プランは flexible mode 不可 → 経由地ループ方式へ変更

実機でキー投入後、`round_trip` 実行時に **「Free packages cannot use flexible mode」** エラー。
- **原因**: GraphHopper無料プランは flexible mode（`ch.disable=true`）を許可せず、`round_trip` も `custom_model` も **flexible 必須**のため無料では使えない。
- **対応（方式変更）**: flexible 不要の **標準ルーティング（CHモード・複数経由地のA→B→…→A）** に切替。
  - `loopWaypoints(lat,lng,targetKm,offsetDeg)`: 既存 `makeLoop` の円周（距離は道なり迂回を見込み `SCALE=0.82` で縮小）上に経由地4点を 20/40/60/80% 位置で配置し、`[起点, wp×4, 起点]` を返す。
  - `roadLoopRoute(waypoints, key)`: `GET /api/1/route?profile=foot&point=…(×6)&points_encoded=false&key=…`（**ch.disable無し＝CHモード＝無料可**）で経由地を道なりに結び、一周ループを得る。
  - `generateCourses(offsets)`: `offsets`（既定 0/90/180/270、`randomOffsets` で「別の案」）ごとに4案生成。各 `paths[0].points.coordinates` を描画、`paths[0].distance` を実測表示。
- **削除**: `round_trip`/`custom_model`/`roadRouteLoop`/「大通りを避ける」チェックボックス（いずれも無料プランで不可のため）。
- **距離**: round_trip 同様ズレるため `SCALE` で補正＋カードに実測・目標比を表示。完全一致はしない。
- **未検証**: 無料キーでの `profile=foot`＋複数経由地ルーティングの実描画（標準ルーティングのため無料で通る想定）。ユーザーのキーで要確認。
- 検証: `node --check` で構文OK、削除シンボルの残存ゼロを確認。

## 【追記2】無料プランの点数上限・現在地・Googleマップ連携

- **「Too many points for Routing API: 6, allowed: 5」**: 無料プランは1リクエスト最大5点。経由地を4→3に削減し `[起点, wp×3, 起点]=5点` に。距離補正 `SCALE` は 0.82→0.88。
- **現在地（Geolocation）**: `file://` やOS設定で失敗 → エラーを code 別（1拒否/2不可/3タイムアウト）に表示、`enableHighAccuracy:false`・`timeout:15000`・`maximumAge:60000` に調整。https（GitHub Pages）＋OS位置情報サービスONで取得可。
- **Googleマップで詳細表示**: 選択中コースのルート点列から経由地を最大8点サンプリングし、`https://www.google.com/maps/dir/?api=1&travelmode=walking&origin=…&destination=…&waypoints=…` を新規タブで開く（`buildGoogleMapsLoopUrl`/`openCourseInGoogleMaps`）。Google側で再ルートするため線は厳密一致しないが、徒歩ナビ・詳細閲覧が可能。押した時のみ座標がGoogleへ送られる旨をプライバシー注記に追記。
