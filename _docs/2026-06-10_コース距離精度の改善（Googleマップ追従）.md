# 2026-06-10 コース距離精度の改善（Googleマップ追従性）

## 背景・課題
道なり周回コースで、アプリ表示の距離（GraphHopper実測）と、「Googleマップで開く」で
表示されるGoogle側の距離が**しばしば大きくズレる**という指摘。

### 原因
`buildGoogleMapsLoopUrl` が GraphHopperの数百点の経路から **8点を“等間隔（番号順）”で間引いて**
Googleに渡していた。Googleは経由地間を自前ルーティングで補間するため、

- 等間隔サンプリングは**曲がり角を取りこぼし直線区間に点が偏る**
- → Googleが別の道（ショートカット等）を選び、距離が10%以上ズレることがあった

## 対応（A＋B）
### A. 経由地を“曲がり角”ベースで抽出（形状ベース）
優先度付きRDP（Ramer–Douglas–Peucker）`simplifyTopK()` を新規追加。
ルート全体から「最も外れている＝曲がり角」の点を優先的に最大K個抽出する。
等間隔サンプリングと違い、**ルートの要点（角）を確実に経由地化**するため、
Googleが同じ道をなぞりやすくなり距離が収束する。

- `perpDistMeters(p, a, b)`: 点→線分の垂線距離（メートル・局所平面近似）
- `simplifyTopK(points, k)`: 端点固定で、最大ズレ区間を優先分割して上位K個の要点を返す（O(n·k)）

### B. 経由地数を増やす
`GMAPS_MAX_WAYPOINTS = 9`（旧8）。GoogleマップURL（`api=1`）の実用上限に配慮しつつ追従性UP。

## 変更ファイル（index.html）
- 追加: `perpDistMeters()` / `simplifyTopK()`（`polylineLength()` の直後）
- 変更: `buildGoogleMapsLoopUrl()` を等間隔サンプリング → `simplifyTopK(pts, 9)` ベースに
  ```js
  const wps = simplifyTopK(pts, GMAPS_MAX_WAYPOINTS).slice(1, -1); // 端点を除いた要点
  ```

## 効果と限界
- 効果: Googleマップ上の距離が**アプリ表示値（GraphHopper実測）に近づく**（数%以内に収束しやすい）。
- 限界（原理的に消えない）:
  - GraphHopper(OSM/foot) と Google(独自/徒歩) は地図データ・歩行ルールが異なり、**数%差は残る**。
  - GoogleマップURLの経由地上限のため、全点（数百点）は渡せない＝完全一致は不可。

## 検証
- インラインJS構文チェック（`node --check`）OK
- L字ルートで角を正しく経由地化、円ルートで k=9 の均等抽出を確認
- 単純形状（角<K）では余剰点が直線上に乗るが、Googleの経路には無害。実際の道路ルートは角が多く全枠が有効活用される。
